第 6 章 · 应用层

应用层离你最近：打开网页、发邮件、查域名，都是它在工作。408 在这一章偏爱“协议端口 + 查询过程 + RTT 计算”，概念不难，但细节容易混。

🎯 学习目标（学完你应该能）
① 区分 C/S 与 P2P 的工作模式；
② 说清 DNS 的层次结构、递归查询与迭代查询的区别；
③ 记住 FTP、SMTP、POP3、IMAP、HTTP 的端口和用途；
④ 说清 HTTP 非持久连接、持久连接、流水线的区别；
⑤ 独立计算非持久/持久/并行连接下的 RTT 总数；
⑥ 说出常见 HTTP 状态码和 DNS 记录类型的含义。

6.1 应用层模型：谁在请求，谁在服务

模型特点典型应用
C/S（客户/服务器）客户端主动请求，服务器固定地址、长期在线；管理集中，服务器可能成为瓶颈Web、邮件、FTP
P2P（对等）每个节点既是客户端又是服务器，直接交换资源；扩展性好，管理困难BitTorrent、区块链
混合模型用中心服务器做索引/登录，实际文件在节点间传输早期 Napster、部分即时通信

应用层协议定义了报文类型、语法、语义和交互规则。它依赖传输层：HTTP/FTP/SMTP 用 TCP，DNS/DHCP/TFTP 用 UDP。

6.2 DNS：把域名翻译成 IP

📖 生活类比
DNS 像电话簿：你记得“张三”这个名字（域名），但打电话需要号码（IP）。DNS 服务器就是帮你查号码的人。名字分层管理（张三→某公司→某部门），号码可以缓存，但会过期。

6.2.1 域名层次结构

www.example.com.
 │    │      │
 │    │      └── 顶级域名（TLD）：com
 │    └───────── 二级域名：example
 └────────────── 主机名：www（由 example.com 的权威服务器管理）

域名从右向左层级降低。根域名服务器管理顶级域（.com、.cn、.org…）；顶级域服务器管理二级域；权威域名服务器保存某个域的具体记录。

6.2.2 递归查询 vs 迭代查询

递归查询迭代查询
谁干活被询问的服务器负责查到最终答案被询问的服务器只返回“下一个该问谁”
典型场景主机 → 本地域名服务器本地域名服务器 → 根/顶级/权威服务器
负担对本地 DNS 负担大对本地 DNS 负担较小，但查询次数多
🔬 实验室：DNS 解析步骤
点“下一步”，看一次 www.example.com 的解析到底经过哪些服务器、谁问谁。

6.2.3 DNS 记录与缓存

记录含义例子
A域名 → IPv4 地址www.example.com → 93.184.216.34
AAAA域名 → IPv6 地址www.example.com → 2606:2800:…
CNAME别名 → 规范域名blog.example.com → example.github.io
MX邮件交换服务器example.com → mail.example.com
NS该域的权威域名服务器example.com → ns1.example.com

DNS 缓存按 TTL 生效：主机、本地 DNS、甚至浏览器都会缓存。缓存能减少查询次数，但域名换 IP 后要等 TTL 过期才全网生效。

📌 408 常问“查询次数”
若主机缓存为空、本地 DNS 缓存也为空，采用迭代查询，则本地 DNS 至少访问根、顶级、权威各一次，共 3 次；主机到本地 DNS 的那一次是递归查询。题目若问“总报文数”，还要加上主机→本地 DNS 的 1 次。

6.3 FTP：两条连接的文件传输

FTP 用两条 TCP 连接：控制连接（端口 21）传命令和响应，数据连接（主动模式端口 20）传文件。控制连接在整个会话期间保持，数据连接每传一个文件建立一次。

模式谁发起数据连接说明
主动模式（PORT）服务器从 20 端口连客户端客户端在防火墙后可能被拒绝
被动模式（PASV）客户端连服务器随机端口更适合客户端在 NAT/防火墙后

FTP 的控制信息是带外传送：控制连接和数据连接分开。它是有状态的，服务器要记住当前目录、登录用户等。

6.4 电子邮件：SMTP 发，POP3/IMAP 收

协议端口方向作用
SMTP25推送（发送）用户代理 → 邮件服务器，或服务器 → 服务器
POP3110拉取（下载）把邮件下载到本地，默认下载后服务器可能删除
IMAP143拉取（同步）在服务器上管理邮件，多设备状态同步
MIME—扩展让 SMTP 能传图片、附件、非 ASCII 文本

一封邮件从 A 到 B：A 的用户代理用 SMTP 把邮件推到 A 的邮件服务器；A 的服务器用 SMTP 推到 B 的服务器；B 用 POP3/IMAP 从自己的服务器取信。邮件服务器之间用 SMTP，用户取信才用 POP3/IMAP。

6.5 WWW 与 HTTP

6.5.1 URL 与 HTTP 方法

https://www.example.com:443/news/index.html?q=408#top
└─协议─┘ └────主机────┘└端口┘└──路径──┘└查询┘└锚点┘
方法作用是否幂等
GET请求资源，参数在 URL 中是
POST提交数据，参数在报文体中否
HEAD只要响应头，不要正文是
PUT / DELETE上传/删除资源是

6.5.2 状态码

类别常见码含义
2xx 成功200请求成功
3xx 重定向301 / 302 / 304永久重定向 / 临时重定向 / 资源未修改（用缓存）
4xx 客户端错误400 / 403 / 404请求语法错 / 禁止访问 / 资源不存在
5xx 服务器错误500 / 502 / 503服务器内部错误 / 网关错误 / 服务不可用

6.5.3 HTTP 报文

请求报文：
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Connection: keep-alive

响应报文：
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 1024
Cache-Control: max-age=3600

...

6.5.4 非持久连接 vs 持久连接

方式做法RTT 开销
非持久（HTTP/1.0）每个对象新建一条 TCP 连接，用完关闭每个对象 2 RTT（TCP 握手 + HTTP 请求/响应）
持久非流水线一条 TCP 连接复用，但请求一个个发首个对象 2 RTT，之后每个对象 1 RTT
持久流水线一条 TCP 连接上连续发多个请求所有对象约 2 RTT（不含传输时间）
📌 并行连接怎么算
浏览器通常对同一服务器开 6 条左右并行连接。若有 N 个对象、6 条并行连接、非持久方式：总 RTT = 2 × ⌈N/6⌉（每个对象仍需 2 RTT，但同时进行）。若题目说“串行”，则总 RTT = 2N。

6.5.5 Cookie 与缓存

Cookie 是服务器保存在浏览器端的小段数据，用于识别用户/会话。响应头 Set-Cookie 下发，之后请求头 Cookie 带回。Web 缓存/代理保存响应副本，用 Cache-Control、If-Modified-Since、304 判断是否还能用。

6.5.6 HTTP 版本演进

版本关键改进
HTTP/1.0默认非持久连接，每个对象一条 TCP
HTTP/1.1默认持久连接、流水线、Host 头、分块传输
HTTP/2二进制分帧、多路复用、头部压缩、服务器推送；仍基于 TCP
HTTP/3基于 QUIC（UDP），减少队头阻塞，0-RTT/1-RTT 建连

6.6 RTT 计算专项

假设每个对象很小，传输时间忽略，只算 RTT。页面含 1 个 HTML + 9 个小图片，共 10 个对象。

方式计算总 RTT
非持久、串行10 × 220 RTT
非持久、6 条并行2 × ⌈10/6⌉4 RTT
持久、非流水线2 + 9×111 RTT
持久、流水线22 RTT
⚠️ 别忘了 DNS 和 TCP
若题目还要求“先 DNS 解析”，且本地无缓存，则要额外加 DNS 查询的 RTT；建 TCP 连接又是 1 RTT。做题时先列时间线：DNS → TCP → HTTP 请求 → 响应，再逐项加。

⚠️ 本章避坑清单

DNS 通常用 UDP 53；区域传送用 TCP 53。HTTP 80，HTTPS 443。
主机→本地 DNS 是递归；本地 DNS→根/顶级/权威是迭代。别把“谁干活”说反。
FTP 控制连接 21，主动模式数据连接 20；控制与数据是两条独立的 TCP 连接。
SMTP 负责“发/推”，POP3 和 IMAP 负责“收/拉”；邮件服务器之间也用 SMTP。
非持久连接每个对象 2 RTT；持久非流水线首个 2 RTT、之后每个 1 RTT。
301 是永久重定向，302 是临时重定向，304 表示可用缓存、没有正文。
HTTP/2 仍基于 TCP；HTTP/3 才改用 QUIC/UDP。

📝 章内练习（8 题 · 基础 → 提高 → 真题）

🟢 第一档 · 基础（3 题）

练习 1 · 考点：DNS 查询方式
主机向本地域名服务器发出查询，希望对方直接返回最终 IP 地址。这种查询方式属于：
A. 迭代查询
B. 递归查询
C. 广播查询
D. 反向查询
答案：B。“你帮我查到最终答案”是递归查询，典型发生在主机→本地 DNS。本地 DNS 向根/顶级/权威服务器逐一询问“下一个该问谁”，属于迭代查询。
练习 2 · 考点：FTP 端口
FTP 控制连接使用的熟知端口是：
A. 20
B. 25
C. 21
D. 80
答案：C。FTP 控制连接用 21，主动模式的数据连接用 20。25 是 SMTP，80 是 HTTP。
练习 3 · 考点：邮件协议
用户从邮件服务器把邮件下载到本地，通常使用：
A. POP3 或 IMAP
B. SMTP
C. FTP
D. DNS
答案：A。SMTP 用于发送/推送邮件；POP3（110）和 IMAP（143）用于从服务器收取邮件。POP3 倾向下载到本地，IMAP 强调服务器端同步。

🟡 第二档 · 提高（3 题）

练习 4 · 考点：HTTP 状态码
HTTP 响应码 304 表示：
A. 请求的资源不存在
B. 资源未修改，客户端可以使用缓存
C. 永久重定向到新地址
D. 服务器内部错误
答案：B。304 Not Modified 表示协商缓存命中，服务器告诉客户端“你缓存的版本还能用”，响应通常没有正文。404 是资源不存在，301 是永久重定向，500 是服务器内部错误。
练习 5 · 考点：非持久连接 RTT
浏览器用 HTTP/1.0 非持久连接请求 1 个很小的对象，忽略 DNS 和传输时间，至少需要几个 RTT？
A. 1 RTT
B. 2 RTT
C. 3 RTT
D. 4 RTT
答案：B。1 个 RTT 建立 TCP 连接，再 1 个 RTT 发送 HTTP 请求并接收响应，共 2 RTT。若题目把 DNS 也算上，还要再加 DNS 查询时间。
练习 6 · 考点：持久连接流水线
一个页面含 10 个很小的对象，使用 HTTP/1.1 持久连接并启用流水线，忽略 DNS 和传输时间，总 RTT 约为：
A. 20 RTT
B. 11 RTT
C. 10 RTT
D. 2 RTT
答案：D。持久流水线只需 1 个 RTT 建 TCP，再用 1 个 RTT 连续发请求并收响应，共 2 RTT。非持久串行是 20 RTT，持久非流水线是 2+9=11 RTT。

🔵 第三档 · 真题风格（2 题）

练习 7 · 考点：DNS 记录类型
要指定某个域名对应的邮件服务器，应配置的 DNS 记录类型是：
A. MX
B. A
C. CNAME
D. NS
答案：A。MX（Mail Exchanger）指定邮件服务器；A 是域名→IPv4，CNAME 是别名，NS 指定权威域名服务器。
练习 8 · 考点：HTTP/1.1 与 HTTP/2
下列关于 HTTP 版本的说法，正确的是：
A. HTTP/1.1 默认使用非持久连接
B. HTTP/2 基于 UDP，因此没有队头阻塞
C. HTTP/1.1 默认持久连接并支持流水线；HTTP/2 多路复用但仍基于 TCP
D. HTTP/3 仍然基于 TCP，只是增加了头部压缩
答案：C。HTTP/1.0 默认非持久；HTTP/1.1 默认持久连接并支持流水线；HTTP/2 用二进制分帧和多路复用，但仍在 TCP 上，因此仍有 TCP 层队头阻塞；HTTP/3 才改用 QUIC（基于 UDP）。
